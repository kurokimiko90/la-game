# 場景製作標準 v2：小鎮地圖 + 自然擺放 + 場景動態

> 日期：2026-09-22｜狀態：已實作，4 個場景都已套用｜之後每個新場景都照這份做
> 預覽圖：`docs/scene-preview/town.png`（整張地圖）、`docs/scene-preview/<scene>.png`（各街區）

## 0. 不能破壞的規則

1. **位置固定**：擺放由 seed 決定，產生後鎖在 `content/layouts/<scene>.json`。動態只能在原位附近小幅晃動：位移約為物件大小的 3–8%、旋轉 ≤ 5°（記憶挑戰的容許誤差至少 40 單位，見 `src/lib/geometry.ts` 的 `isNearItem`）。
2. **找得到**：每個物件至少露出 60%（`MIN_VISIBLE`，用外框估算，連其他場景的物件一起算），而且底線不能超出所屬區域。build 時檢查，沒過就失敗。
3. **動態不能變成線索**：會動的物件不超過場景物件的 30%，每個區域的背景也要有動態。否則玩家會學到「會動的就能點」。
4. **背景裝飾不能長得像可點的物品**：例如背景不畫鳥、樹、長椅、欄杆、路燈、斑馬線、貨架，因為它們都是單字（改用綠籬、草叢、花台、鋪面）。
5. **系統開啟「減少動態」時全部停止**（`globals.css` 的全域規則）。E2E 也因此用 `reducedMotion: 'reduce'`，讓點擊位置穩定。
6. **物件 id 跨場景不能重複，區域不能互相重疊**：所有場景在同一張地圖上，違反時 build 會失敗。

## 1. 小鎮地圖

所有場景是同一張 2D 地圖上的街區（3600×2600）。地面是 3/4 俯視，物件是正面扁平圖、直立擺放（和 RPG 地圖一樣）。可以上下左右平移，最小縮到看見整個小鎮，最大放大到預設的 3 倍。

```
 ┌──────────── 公園 ─────────────┬西岸┬──── 河邊東岸 ────┐
 │ 入口  噴泉廣場  遊樂場   湖 ≈≈≈≈≈≈≈≈ 河 │ 橋               │
 │  │   └─ 商店、咖啡店建築 ─┘       │ ≈≈ │ 碼頭（燈塔）      │
 │ ══ 商業街：路口 商店 咖啡店 公車站 ══│ ≈≈ │ 露天座位         │
 │ 超市（無屋頂剖面）：入口 生鮮 冷藏 收銀│ ≈≈ │ 河岸步道         │
 └──────────────────────────────────┴────┴──────────────────┘
```

- **場景之間靠地形銜接**：公園步道往南接商業街，綠籬把公園和商店建築隔開；湖水經小溪流進河；超市在商業街南側，門開在面向街道的後牆上。
- **地形在 `src/components/scene/WorldBackground.tsx`**。道路、河、牆的座標必須和 `scene-config.json` 的區域與地帶一致，改地圖時兩邊一起改。
- **網址 `/scene/<id>` 代表「目前街區」**：關卡、提示、進度都以它為準。點頂部導覽列的其他街區會移過去；在選關或自由探索時，會同時切換目前街區。
- **自由探索時**：任何已解鎖街區的物品都能點。未解鎖的街區蓋一層霧，點了會提示解鎖條件。
- **左下角小地圖**：顯示街區分布和目前看到的範圍，點一下就移過去。畫面外的街區與背景分區會暫停動畫。

## 2. 擺放

### 2.1 場景設定（`content/scene-config.json`）

```json
"world": {"width": 3600, "height": 2600},
"park": {
  "name": "公園", "icon": "fountain",
  "zones": {"entrance": [0, 0, 650, 1130], "plaza": [650, 0, 1300, 740], "lake": [1950, 0, 2600, 1130]},
  "bands": {
    "ground": {"top": 230, "scale": [0.95, 1.05], "override": {"lake": {"top": 790}}},
    "sky":    {"top": 220, "bottom": 420, "layer": 3, "float": 150, "zones": ["plaza", "playground"]},
    "water":  {"top": 430, "bottom": 610, "layer": 1, "zones": ["lake"], "x0": 2040, "x1": 2520}
  },
  "place":    {"kite": "sky", "balloon": "sky", "rowboat": "water"},
  "clusters": [["picnic-blanket", "picnic-basket", "sandwich"]],
  "loose":    ["book", "straw-hat", "sunglasses", "ball"],
  "noFlip":   [],
  "motion":   {"tree": "sway", "balloon": "bob", "kite": "drift", "ball": "wobble"}
}
```

**區域（`zones`）**：`[x0, y0, x1, y1]`，是地圖上的矩形。名稱來自 manifest。所有場景的區域不能重疊。

**地帶（`bands`）**：區域裡可以放東西的範圍，y 指物件**底線**。一定要有 `ground`；沒寫在 `place` 裡的物件都放這裡，預設範圍是整個區域扣掉內距。

| 欄位 | 意思 |
| --- | --- |
| `x0` / `x1` / `top` / `bottom` | 地圖座標，和區域取交集（例如河東岸 `x0: 2980`） |
| `levels` | 固定幾層檯面，物件底線只落在這幾個 y（例如蔬果台 `[2110, 2225]`） |
| `gaps` | 不能放的 y 範圍（例如車道 `[[1245, 1515]]`，檯面後方） |
| `zones` | 只在這些區域有效；其他區域的物件改放 `ground` |
| `override` | 針對單一區域覆寫上面任一欄位 |
| `inset` | 離區域邊界的距離（預設 30） |
| `scale` | `[上, 下]` 的縮放，依 y 內插；3/4 俯視時兩個值差不多 |
| `layer` | 繪製層：水面 1 → 地面、檯面 2（預設）→ 天空 3 |
| `float` | 飄在空中的高度，地上會畫影子（風箏、氣球） |
| `look` / `base` | 背景要畫出來的檯面（`stand`、`chiller`、`checkout`、`cafe-counter`、`table`、`jetty`），`base` 是正面落地的 y |

**其他欄位**

| 欄位 | 意思 |
| --- | --- |
| `place` | 物件 → 地帶 |
| `rows` | 沿一條折線等距排：`{"note": "說明", "points": [[x, y], …], "items": ["a", null, "b"]}`。第 i 個物件的**底線中心**在折線長度的 (i + 0.5) / n 處，`null` 佔位留空。用在「沿步道、貼門面、排在檯面上」這種有邏輯的排列 |
| `spots` | 指定單一物件的底線中心：`{"gate": [330, 1110]}`。用在門、噴泉、車子、船這種位置有意義的物件 |
| `clusters` | 成群擺放。第一個是主體，其他物件圍在它旁邊，可以疊在主體前面，但不能整個蓋住它。成員要和主體同一個區域（build 會檢查） |
| `loose` | 可以歪倒的散落小物，會傾斜 ±20°；沒列出的物件一律正立 |
| `noFlip` | 不能左右鏡像的物件（預設都可以鏡像，因為物件圖不含文字） |
| `motion` | 物件 → 動態類型，見 §3.1 |

拼錯的物件 id、不存在的地帶、區域沒有位置、物件出現在多個錨點、群組跨區域等問題，都會在 build 時擋下（`scripts/lib/scene-config.mjs`）。

**擺放邏輯（2026-09-23 起，前 4 區已套用）**：先想每個物件「跟什麼有關」，再決定用哪種方式——貼著地形（步道兩側、人行道貼門面、河岸欄杆）用 `rows`；位置本身有意義的用 `spots`；依附另一個物件的用 `clusters`；真的沒有關係的小物才交給隨機。高的物件放在離鏡頭遠的一側（例如北側人行道），免得看起來插進馬路。

### 2.2 演算法（`scripts/lib/layout.mjs`）

1. **放置順序**：錨點物件（`rows`、`spots`）先放，位置固定、大小不抖動；其他物件裡大物件和群組主體先放，群組成員最後放。擺一個場景時，其他場景已鎖定的物件當作障礙物（`obstacles`）一起避開。
2. **選位置**：每個物件在所屬地帶內抽 24 個候選位置，取和已放物件重疊最少的；縮放隨機 ±8%。
3. **群組**：成員的底線落在主體底線 −10 到 +45 之間，x 在主體附近；和主體的重疊只算 0.4 倍。
4. **變化**：`loose` 物件傾斜 ±20°；其他物件有 50% 機率鏡像。
5. **驗收**：可見比例 ≥ 60%。沒過就換 seed 重排，最多 20 次；還是失敗就報錯，並列出有問題的物件。

**自動排列（`"arrange": "auto"`，自動擴展的街區用；手寫的 rows / spots 優先）**

1. 檯面、牆腳設備、軌道、車道：各層一排，等距排開。
2. 地面：大 → 中 → 小，由後往前一排一排，一排放不下就換行；散落小物也排（保留傾斜）。
3. 群組成員緊貼主體排在同一排；成員比主體大的群組不算（不然大的會蓋住主體）。
4. 牆上的掛件最後排。每一排都只用「沒被已排物件擋住」的空隙（只看上下有重疊的），所以牆腳設備和後排大物件會交錯。
5. 被擋太多的物件（和擋住它的）改成隨機，其他照排，最多 6 輪；還不行整區退回隨機。改成隨機的物件會印 ⚠️。
6. 水上、天空的物件照舊隨機。

2026-09-23 已對 7 個自動生成的街區 `--reset` 套用；機場的入口和登機門各有 5 個物件退回隨機，月台 5 個。

### 2.3 鎖定與手改

- `content/layouts/<scene>.json` 一行一個物件：`{ x, y, w, h, rotate, flip }`。可以直接手改；build 只讀這個檔，並用 `checkLayout` 再檢查一次（跨場景一起算遮擋）。
- SVG 重生後長寬比變了：build 會保留寬度和底線，自動重算高度。
- `npm run content:layout -- <scene> --reset` 會整個重排。**場景上線後不要用**，因為玩家記住的位置會全部改變。

## 3. 動態

### 3.1 物件動態（`scripts/lib/motion.mjs` + `globals.css` 的 `.motion--*`）

| 類型 | 動作 | 支點 | 用在 |
| --- | --- | --- | --- |
| `sway` | 左右擺 ±2°，週期 3–5 秒 | 底部中心 | 植物、布料：樹、樹叢、花壇、花束、旗子、遮陽傘、釣竿 |
| `bob` | 上下浮動（高度的 3%）+ 旋轉 ±1.5°，週期 2.5–4 秒 | 中心 | 水上、空中：氣球、划艇、觀光船 |
| `drift` | 8 字形小幅飄移 + 旋轉 ±5°，週期 5–7 秒 | 上方 | 風箏 |
| `wobble` | 靜止一陣子後抖動約 1 秒，週期 6–10 秒 | 底部中心 | 會震動或被碰的東西：手機、球、購物車、車子 |

- 週期、相位、幅度 ±20% 在 build 時用 item id 當 seed 算好，寫進場景 JSON。
- 渲染（`SceneItemNode.tsx`）：外層 `<g transform>` 負責傾斜和鏡像，巢狀 `<svg>` 裡面的 `<g>` 負責動畫；位移用 %，大小不同的物件晃動比例一致。

### 3.2 背景動態（`src/components/scene/Ambient.tsx`）

`WaterShimmer`（湖、河的水紋）、`SwayTufts`（草叢、花台）、`Glow`（窗戶、壁燈）、`HangSwing`（超市吊牌）。背景裡重複的元素用 `scatter(seed, …)` 抖動，不要等距排列。

### 3.3 效能（2026-09-22 實測，桌機 Chrome dev 模式，有 GPU）

| 條件 | 閒置 | 平移 |
| --- | --- | --- |
| 預設縮放（約 78 個動畫） | 100 fps | 99 fps |
| 預設縮放，CPU 降速 4 倍 | 99 fps | 89 fps |
| 看整個小鎮（134 個動畫），CPU 降速 4 倍 | 100 fps | 98 fps |

⚠️ **手機實機還沒測。** Headless Chrome 是軟體繪圖，量到的數字不能當參考。

## 4. 新場景製作流程

1. **找位置**：在地圖上找空間，必要時加大 `world`。決定它和現有場景怎麼接（道路、河、步道），在 `WorldBackground.tsx` 畫地形；每個區域至少要有 1 個背景動態，而且不畫像單字物品的東西。
2. **manifest**：單字、描述、`sizeHint`。
3. **scene-config**：`name`、`icon`、`zones`（地圖矩形）、`bands`、`place`、`clusters`、`loose`、`motion`。需要檯面時，在地帶加 `look`；要新樣式就在 `Surfaces.tsx` 加一種。另外在 `TownMinimap.tsx` 的 `COLORS` 加上這個場景的顏色。
4. **擺放**：`npm run content:sync-svg` → `npm run content:layout -- <scene>` → `npm run content:scenes` → `npm run content:scene-preview`，看預覽圖後手改 `content/layouts/<scene>.json`，再預覽一次。
5. **音檔**：`npm run content:audio`（edge-tts 底稿）→ `npm run content:voice -- <scene>`（ChatGPT 的聲音，需要 miko-ws、ffmpeg、whisper-cli）。
6. **檢查**：`npm test`、`npm run test:e2e`，並在手機上看一次動態和平移。
7. **鎖定**：上線後 `content/layouts/<scene>.json` 視為鎖定，不再 `--reset`。
