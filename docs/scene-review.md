# 四個場景的參考與擺放修訂

2026-09-27。範圍：動物園、植物園、學校、班級教室。參考作品的空間設計方法，結合真實場所的功能關係；目前仍是風格化的語言學習找物遊戲，並非按比例重建實際園區。

## 後續場景沿用的規則

1. 先找有來源的真實場所案例，寫下入口、動線、功能區、主要家具和物件依附關係，再排元素。不得只以詞彙類別均分四格。
2. 大地標定位，小物圍繞用途成組。尺寸要有層次；小物不能為了湊可見度而放大成家具大小。
3. 清楚區分牆面、檯面、地面和水面。水生植物在水中，文具在桌面，掛件靠牆，動物留在指定棲地。
4. 走道是必要留白，不用地面物件配額填滿。生成提示已移除「至少一半放地上」，並要求僅允許 ground 時選適合落地的物件。
5. 用低對比俯視輪廓畫背景；相似的可點目標仍用清晰正面輪廓。教室背景座位因此採俯視桌椅。
6. 記憶玩法的位置保持鎖定。這次屬使用者要求的場景重排，後續一般補物件不再重置既有位置。
7. 同時看完整場景和正常遊玩縮放。檢查高物件是否越界、桌面是否承托小物、門口是否被堵、目標是否可點。縮圖檢查不能替代實際點擊。

## 資料與驗收

- 配置來源：`content/scene-config.json` 的 `terrain.zones[].details`；物件位置在 `content/layouts/*.json`。學校的家具分組在 `content/stages/school.json`。
- `SiteFeatures.tsx` 繪製步道、棲地、植床、池塘和家具。`terrain.openPlan` 讓教室共用一圈外牆。
- `scripts/lib/site-plan.mjs` 在內容建置時檢查範圍、重複 id、所屬區域、物件底線中心是否落在指定棲地／承托區，以及是否佔用走道。
- 這是底線中心約束，不是完整碰撞、動物福利或建築規範驗證；高物件越界和家具腿等視覺問題仍需預覽檢查。
- 動物園、植物園、班級教室各 12 個目標；學校 70 個。前三個仍屬低密度版本，不等同完成高密度商業遊戲美術。

本輪驗證：`npm run content:scenes`、`npm run typecheck`、`npm run lint`、`npm test` 全部通過（23 個測試檔、267 個測試）。桌面 Chrome 以實際導覽、平移和滑鼠點擊測試獅子、蓮花、仙人掌、黑板、教室鉛筆、校園籃框與學校鉛筆，均顯示對應中英文；四個場景未出現瀏覽器執行錯誤。另逐張檢查完整場景預覽，修正黑板輪廓、池水邊界與球具越界。

## 下一輪優先順序

1. 在維持可點性的前提下，補充有用途的環境細節與局部非對稱配置，減少矩形展區的整齊感。
2. 為植物和動物素材增加明確的物種特徵，目前部分輪廓仍偏圖示。
3. 增加可理解的環境小互動及情境提示，再擴充詞彙密度；不要只往空位塞更多目標。
4. 針對手機尺寸做觸控與導航測試；本輪瀏覽器驗證使用桌面 Chrome。

## 其餘場景的配置驗收（2026-09-28）

其餘 24 個既有街區也逐一以完整畫面檢視；其中 4 個核心手繪場景使用手寫 `rows`、`spots` 和 `clusters`，20 個擴展街區使用 `content/stages/*.json` 的情境分組。這些設定讓物品由用途決定位置，而不是依字彙類別或大小平均分散。學校同時使用兩種方式，因為它需要校園地形和室內工作站。

| 場景類型 | 已套用的空間順序 | 對應街區 |
| --- | --- | --- |
| 公共服務與交通 | 入口／人行空間 → 服務或查驗 → 等候、工作或月台；車輛只在車道、軌道或停靠區 | 車站、醫院、機場、郵局、消防局、銀行、警察局 |
| 零售與餐飲 | 門面 → 展示或備料 → 櫃台與結帳；手持小物放在展示架、檯面或推車 | 餐廳、麵包店、服飾店、花店、書店、文具店、超市 |
| 學習、文化與休閒 | 入口 → 主要活動區 → 閱讀、展示、練習或後勤；桌椅、展櫃與器材之間保留通道 | 圖書館、電影院、博物館、沙灘、健身房、學校 |
| 戶外與住家 | 入口與步道先確立，再配置門廊、草坪、休憩、灌溉與室內機能 | 公園、商業街、河畔、我的家、動物園、植物園 |

公共空間不把通道當成可用的填充區。這個選擇參考了 [美國國家公園管理局的展覽動線指引](https://www.nps.gov/features/hfc/guidelines/)，其中要求展覽通道保持無障礙；[Access Board 的圖書館標準](https://www.access-board.gov/adaag-1991-2002.html) 將閱讀、書庫與借還書視為不同功能區，並要求桌椅及書庫間有通行淨空；[加州醫療設施設計機構的功能計畫](https://hcai.ca.gov/document/pin-57-functional-program/) 將公共等候、病患服務與內部服務動線分開。

### 全場景驗收結果

- 28 個場景均已產生完整預覽，並檢查入口、車道／水域、檯面、家具和主要留白是否一致。
- 所有自動街區均保有手寫的功能分組；新住家已加入相同流程。生成提示也已要求保留走道，避免小物為填滿畫面而落在地面。
- `scene-site-plan.mjs` 已為其餘自動街區實際繪出低對比通行帶；車站、機場、醫院、郵局、銀行等另有排隊欄，戶外入口區有植栽與遮蔭，月台、潮池與警局訓練場也有用途輪廓。原有手寫分區優先保留。
- 內容建置會檢查可見比例、越界、跨場景遮擋、情境資料及指定棲地／水域／走道；桌面 Chrome 已逐一移動鏡頭並點擊 28 個場景的代表物件，全部顯示對應英文，且沒有執行階段錯誤。

## 場所結構重做（2026-09-29）

先前的 `STRUCTURES` 只有配色與兩條分隔線；完整截圖顯示其餘街區依然像同一個四區模板。這個判斷已更正。現在 `VenueStructure.tsx` 逐一列出 19 個自動街區的四個功能區：例如車站廣場／大廳／閘門／月台、機場車道／報到／安檢／登機、圖書館門廳／書庫／閱讀、消防局前院／車庫／裝備／勤務。各區有不同的地面輪廓，場所也使用相應牆面材質。室內外接縫由 `IndoorEnvelope` 按實際室內區域計算，戶外廣場、花園與海灘不再整圈套建築外牆。

參考平面與用途關係：[JR 東海車站平面圖](https://global.jr-central.co.jp/en/info/station/)、[紐約公共圖書館導覽](https://visitorcenter.nypl.org/)、[史密森尼自然史博物館地圖](https://naturalhistory.si.edu/visit/map)。遊戲是風格化示意，沒有照抄實際場所的尺寸或平面。目標物位置仍由既有 `content/stages` 和 `content/layouts` 決定；背景建築不當作新的可找物件。
