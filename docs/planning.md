## 0. 一句話概念

玩家在一座由多個場景組成的「記憶小鎮」裡找東西。每個物品都固定在同一個位置，點擊任何物品都會顯示名稱並播放發音——用**空間位置記住單字**（記憶宮殿法），用**找東西的樂趣**推動重複練習。

## 1. 立項（Concept / Greenlight）

### 1.1 遊戲概念

| 項目 | 內容 |
| --- | --- |
| 類型 | 2D 隱藏物件（Hidden Object）＋ 語言學習 |
| 學習語言 | 英語 + 日語；同一場景對應多種語言（物件圖不含文字，單字與音檔按語言切換） |
| 目標用戶 | 語言初學者（A1–A2），成人與青少年自學者為主，親子為輔 ⚠️ 假設 |
| 平台 | Web（PWA）先行 → 打包上架 iOS / Android |
| 核心體驗 | 沉浸在生活場景中，邊找邊聽，自然記住「什麼東西在哪裡、叫什麼」 |
| 單局時長 | 一個階段 3–5 分鐘，適合碎片時間 |

### 1.2 核心玩法循環

```
進入小鎮 → 選目前街區與關卡 → 看任務清單（本階段要找的 N 個物品）
   → 探索地圖（拖曳 / 縮放 / 小地圖）
   → 點擊任意物品：顯示名稱 + 播放發音（物件音效未做）
   → 點中目標：收集 ✓
   → 集滿清單：階段完成 → 解鎖下一階段 / 下一個街區
   → 點過的單字進入詞彙本 → 隔天回來複習（間隔重複，未做）
```

關鍵設計：**點錯不懲罰**。點到非目標物品同樣會顯示名稱和發音——「找錯」本身也是學習。

### 1.3 市場與競品

| 競品 | 類型 | 可借鏡 | 差異 |
| --- | --- | --- | --- |
| Duolingo | 遊戲化語言學習 | 連續打卡、短時長 | 無空間情境，詞彙脫離場景 |
| Drops | 圖像詞彙 | 以圖代譯、5 分鐘一局 | 無探索與空間記憶 |
| Influent（Steam） | 3D 房間點物學詞 | 「點物件聽發音」概念最接近 | 3D、單一房間、PC 限定 |
| Noun Town（VR） | VR 城鎮語言學習 | 城鎮 + 物件互動 | 需要 VR 裝置，門檻高 |
| Hidden Folks | 手繪隱藏物件 | 找物樂趣、美術風格、點擊回饋音效 | 非語言學習 |

> 市場規模、下載量、Steam 評論數等數據：⚠️ 待調研補充。

### 1.4 競爭優勢

1. **記憶宮殿結構**：物品位置固定，所有場景是同一張小鎮地圖上的街區，空間記憶與詞彙綁定。
2. **階段遞進**：同一場景從「看圖找」→「看字找」→「聽音找」→「憑記憶找」，重複遊玩有新挑戰。
3. **輕量平台**：2D + 手機 / Web，比 3D / VR 競品門檻低。
4. **內容可擴展**：新場景 = 新詞彙包，資料驅動；新場景用街區模板自動產生地形，規劃、素材、整合全自動（[expansion.md](expansion.md)）。

### 1.5 技術可行性

| 項目 | 方案（現況） | 風險 |
| --- | --- | --- |
| 場景渲染 | React + SVG：一張小鎮地圖（地形在 `WorldBackground.tsx`）+ 每個物件一個內嵌 SVG | 7 個場景、339 個物品，Retina（DPR 2）桌機 Chrome 實測（2026-09-22）：production 閒置 / 拖曳 / 滾輪縮放 98–100 fps；`next dev` 只有 17–82 fps、縮放時最長卡 600ms，**試玩和體驗要用 production build**：`npm run play`（build 到獨立的 `.next-play`、開在 3220）。不要和 `.next` 共用：自動擴展跑 `test:e2e` 會重建 `.next`，正在跑的 production 伺服器畫面還在但 JS 失效，完全不能操作（2026-09-22 踩到）；**手機實機未測** |
| 點擊判定 | 物件 SVG 內嵌，形狀就是點擊範圍；SVG 先經白名單清洗 | 小物品誤觸 → 最小點擊尺寸規範（尚未訂） |
| 擺放 | seed 自動擺放 → 鎖定在 `content/layouts/`，可手改；build 時檢查可見比例 ≥ 60%、底線不超出區域 | 上線後改位置會打亂玩家記住的位置 |
| 物件美術 | miko-ws Lane B 已生成 132/132 個 SVG，見 [svg-assets.md](svg-assets.md) | 動物 / 人物 Lane B 畫不了，要走 Lane A，兩種畫風需統一 |
| 發音 | edge-tts 底稿（英、日、中）＋ miko-ws 的 ChatGPT 聲音覆蓋，whisper 切割與驗收，見 §3.5.1 | 讀音未經母語者檢查；不同 ChatGPT 帳號聲音可能不一致；單字改了不會重錄 |
| 存檔 | localStorage，讀取時逐欄驗證；之後加帳號 + 雲端同步 | 跨裝置進度、清除瀏覽器資料會遺失 |
| 框架 | Next.js 16 + React 19 + TypeScript + Tailwind v4；PWA 與 Capacitor 尚未設定 | 商店審核對 WebView 應用的要求 |

結論：無高風險技術難點，主要成本在**美術與配音內容**；目前最大的未知是手機效能。

### 1.6 成本預估（人月，⚠️ 假設）

| 角色 | 配置 | 投入 |
| --- | --- | --- |
| PM / 策劃 | 1 人 | 約 7 人月 |
| 前端程式 | 1 人 | 約 6 人月 |

| 配音 | miko-ws 語音生成；核心詞是否仍外包真人錄音待定（§8） | 每場景約 70 詞 × 2 語言，場景持續自動增加 |
| 其他 | — | 開發者帳號、主機、測試招募、宣發 |

金額待外包報價後填入。

### 1.7 商業模式與回本模型

**推薦：免費試玩 + 買斷解鎖**。第 1 個場景（公園）免費，完整版或場景包付費解鎖。理由：內容量有限時，買斷比訂閱容易讓用戶接受；之後有穩定更新節奏再評估訂閱。
次要收入：學校 / 補習班授權（B2B）。

```
收入       = 下載量 × 付費轉化率 × 客單價 × (1 − 平台抽成)
回本下載量 = 總成本 ÷ (付費轉化率 × 客單價 × (1 − 平台抽成))
```

示例（⚠️ 全為假設值）：總成本 US$50,000、轉化率 3%、客單價 US$4.99、抽成 30%
→ 每個下載貢獻約 US$0.105 → 回本需約 48 萬下載。
→ 說明純 C 端買斷回本壓力大，**B2B 授權與控制美術成本**是回本的關鍵變數。

### 1.8 Go / No-Go 判斷標準（建議）

- 原型測試中 ≥ 70% 測試者不經說明即可完成階段 1，且表示想玩下一階段。
- 隔天詞彙回憶測試（看圖說出單字）正確率 ≥ 50%。
- 單個場景的美術 + 配音成本在預算內。

目前三項都還沒有數據。

### 1.9 PM 關注點

- A：資源是否到位？時程是否可行？「找東西 + 學單字」是否真的好玩，而不只是有用？
- T：定義原型要驗證的問題；組織試玩並收集回饋。

## 2. 前期製作（Pre-production）

### 2.1 里程碑 1：原型（約 3–4 週）

**原訂範圍**：1 個場景（公園）、占位圖、TTS 發音、階段 1–2、點擊顯示名稱 + 發音。

**實際（2026-09-22）**：4 個場景、正式 SVG、階段 1–4 全部、詞彙本、小鎮地圖都做了；**試玩還沒辦**，所以下面 4 個問題都沒有答案。

**要回答的問題**：

1. 點擊 → 名稱 + 發音的回饋是否清楚、有趣？
2. 找東西的難度是否合適（太簡單無聊、太難挫折）？
3. 手機上拖曳 / 縮放 / 點小物品的操作是否順手？
4. 玩完後是否真的記得單字？

**產出**：可玩原型 ✅、試玩紀錄（5–10 人）❌、玩法調整清單 ❌。

### 2.2 里程碑 2：垂直切片（約 6 週）

**範圍**：公園場景完整美術、真人發音、階段 1–4 全部、詞彙本、基本音效與背景音樂。

- 已提前完成：階段 1–4、詞彙本。
- 還要做：公園補上動物 / 人物並統一畫風、真人發音、音效與背景音樂、手機實機測試。

**通過標準**：外部試玩者能完整玩完一個場景，美術風格定稿，單場景製作流程（SVG 生成 → 場景擺放 → 配音 → 設定表）跑通並測出工時。
流程已寫成 [scene-standard.md](scene-standard.md) §4，但還沒有照流程從頭做一個新場景，工時未測。

### 2.3 美術方向

- 物件是正面平視的扁平向量風格（SVG），由 miko-ws 批量生成；地面是 3/4 俯視的小鎮地圖，物件直立站在地圖上（和 RPG 地圖一樣），可上下左右平移縮放。
- 物件本身不用俯視：路燈、紅綠燈、腳踏車等從正上方看認不出來，不利學單字。
- 物品需要「找得到但不能一眼看到」：靠成群擺放、互相遮擋、尺寸差異、散落小物歪倒製造難度；每個物件至少露出 60%。
- 物件圖與背景都不放任何文字或數字，確保同一場景可以用於各種語言。
- 背景不畫長得像單字物品的東西（鳥、樹、長椅、欄杆等），改用綠籬、草叢、花台、鋪面，避免玩家點了沒反應。
- 動態：會動的物件不超過場景物件的 30%，每個區域的背景也要有動態，避免「會動的就能點」變成線索。
- 動物與人物 Lane B 畫不了，原型先不放，之後走 Lane A（PNG）再統一畫風。

### 2.4 團隊配置

PM / 策劃 1、前端 1、插畫外包 1–2、配音外包；QA 由團隊內部 + 封測玩家承擔。

## 3. 正式開發（Production）— GDD 核心

### 3.1 場景設計

所有場景是同一張小鎮地圖上的街區，靠道路、河流、綠籬銜接（地圖配置見 [scene-standard.md](scene-standard.md) §1）。路線順序：

```
公園 → 商業街 → 河邊商業區 → 超市 → 車站 → 餐廳 → 學校 → …（自動擴展接在後面）
```

- **解鎖規則**（2026-09-22 改）：路線上前 8 個場景一開始就開放（`FREE_SCENE_COUNT`，`src/lib/progress.ts`）；第 9 個起，前一個場景過了階段 1 才開下一個；同一場景的階段依序解鎖。未解鎖的街區蓋一層霧，點了會提示解鎖條件。
  - 改的原因：原本只開公園，一開始能玩的太少。
  - 目前只有 7 個場景，所以現在全部開放；第 9 個場景加入後才會第一次出現上鎖。
  - 和 §1.7「只有公園免費」不一致，見第 8 節。
- **物品數**：原定每場景 40–60 個，目前 30–35 個（暫緩的動物 / 人物 16 個不含在內），見第 8 節。
- 每個場景劃分 4 個區域，形成記憶宮殿的「路線」。

| 場景 | 物品數 | 區域（路線） | 物品示例 |
| --- | --- | --- | --- |
| 公園 | 33 | 入口 → 噴泉廣場 → 遊樂場 → 湖邊 | 長椅、噴泉、溜滑梯、鞦韆、風箏、路燈、野餐墊、小船 |
| 商業街 | 34 | 路口 → 商店 → 咖啡店 → 公車站 | 紅綠燈、斑馬線、郵筒、自動販賣機、消防栓、馬克杯、公車 |
| 河邊商業區 | 30 | 橋 → 碼頭 → 露天座位 → 河岸步道 | 橋、遊覽船、欄杆、燈塔、釣竿、腳踏車、救生圈、菜單 |

### 3.2 階段設計

每個場景 4 個階段，物品位置不變，提示逐步減少（已實作，規則在 `src/lib/stages.ts`）：

| 階段 | 名稱 | 提示方式 | 目標數 | 找的方式 | 學習目的 |
| --- | --- | --- | --- | --- | --- |
| 1 | 看圖找 | 圖示 + 文字 + 發音 | 10 | 清單，任意順序 | 認識物品 |
| 2 | 看字找 | 圖示 + 文字 + 發音 | 8 | 清單，任意順序 | 字形連結物品 |
| 3 | 聽音找 | 圖示 + 發音 | 10 | 一次一個 | 聽力辨識 |
| 4 | 記憶挑戰 | 物品全部隱形，聽到單字後點出它**原本的位置** | 10 | 一次一個 | 記憶宮殿式回憶 |

- 記憶挑戰的判定：點在物品外框外擴至少 40 單位（或物品短邊的 25%）以內就算對；同一個物品點錯 3 次直接揭曉位置，算完成但扣星。
- **自由探索**：不設目標，任何已解鎖街區的物品都能點。

進階（上線後）：句子找物，例如「長椅下面的貓」，帶入方位詞與短句。

### 3.3 互動規則

- **點擊任何物品**：彈出名稱（英語或日語）＋ 播放發音。可在首頁切換「中文翻譯」「假名讀音」（日語）的顯示。物件音效（如噴泉水聲）還沒做。
- **點擊判定**（2026-09-22 改）：先看有沒有點在物件形狀上；沒有的話，點在物件外框（再外擴 10 個螢幕像素）內也算，重疊時取最小的物件。原因：繩子、筷子這類細的或有空隙的物件，只點形狀時約一半位置點不到，玩家會以為「點了沒反應」。
- **點到背景**：關卡中顯示「這裡沒有物品，再找找看」。背景也畫了櫥窗、沙坑、貨架、冰櫃、桌子等和物品同名的東西，不給回饋會被當成壞掉。
- **點中目標**：收集動畫，清單打勾。
- **提示**：看圖、看字、聽音每關 3 次，記憶挑戰 10 次（2026-09-22 改，原本 3 次太難）；使用後鏡頭移到目標所在區域並讓區域閃爍，聽音 / 記憶關卡會再唸一次單字。
- **無時間限制、無失敗**。
- **地圖操作**（2026-09-22 改，判斷邏輯在 `src/lib/controls.ts`）：
  - 拖曳：平移。縮小到地圖比畫面小時，也能在畫面範圍內拖動（原本會強制置中鎖住，縮小後就拉不動）。地圖上的游標是張開的手，拖曳中變成抓住的手；物品上是手指，面板和按鈕維持原本的游標。拖曳和點擊改用 `buttons` 判斷左鍵按下 / 放開：實測有滑鼠讓 Chrome 以為右鍵一直按著（`buttons=2`），這時按左鍵依 Pointer Events 規格只有 `pointermove`、沒有 `pointerdown` / `pointerup`，原本的寫法拖不動也點不到物品（2026-09-22 踩到，`primaryButtonChange`）。
  - 滑鼠滾輪：以游標為中心縮放，往上放大、往下縮小，一格約 20%。
  - 觸控板：捏合縮放；左右滑橫向平移；上下滑也是縮放（和 Google Maps 一樣，原本是平移）。
  - Shift + 滾輪：橫向平移。手機：雙指縮放。
  - 鍵盤（整頁有效，不用先點地圖）：`+` / `=` 放大、`-` 縮小、`0` 看整個小鎮、方向鍵 / WASD 平移。焦點在輸入框或語言切換時不攔截；⌘ / Ctrl 組合鍵留給瀏覽器。
  - 右側按鈕：放大、縮小、看整個小鎮，滑過會顯示對應快捷鍵。
  - 選關、結算畫面：遮罩不擋滑鼠，面板外可以拖曳、縮放地圖；面板上的滾輪留給面板自己捲動。
  - 只用 Playwright 模擬的滾輪測過，還沒在實體滑鼠、觸控板上試。
- **星級只看求助程度**：提示次數 + 被揭曉的物品數 = 0 → 3 星，≤ 2 → 2 星，其餘 1 星。完成時間只記最佳紀錄，不影響星級（原規劃把時間算進星級，實作時拿掉，避免時間壓力）。

#### 3.5.1 發音生成：edge-tts 底稿 + ChatGPT 的聲音覆蓋

> 2026-09-22 起。實作在 `scripts/build-audio.mjs`、`scripts/build-voice.mjs`、`scripts/lib/voice-take.mjs`、`scripts/lib/voice-cut.mjs`（當天還沒 commit）。語言：英語、日語、中文（zh-TW）。

**第 1 層：edge-tts 底稿**（`npm run content:audio` → `build-audio.mjs`）

- 本機 edge-tts：英語 en-US-JennyNeural 念 `en`、日語 ja-JP-NanamiNeural 念 `ja.text`、中文 zh-TW-HsiaoChenNeural 念 `zh-TW`，語速都是 −10%。
- 用途是保證每個詞都有聲音。只補缺的檔；`--force` 全部重做，但已經通過 ChatGPT 驗收的詞一律不動。

**第 2 層：ChatGPT 的聲音**（`node scripts/build-voice.mjs [場景] [--lang=en,ja,zh] [--force] [--recut]`）

1. 一個場景、一種語言做成一份朗讀稿（一行一個詞：英語「Bench.」，日語、中文「ベンチ。」），送 miko-ws `/api/llm/voice`（`engine: 'gpt'`）念一次，原始 AAC 存到 `.cache/voice-takes/<scene>/`。
   - miko-ws 依序試 ChatGPT 帳號；全部失敗時它會退回 edge-tts，build-voice 把這種情況算失敗，不收合成音。
   - ChatGPT 回的稿子和朗讀稿不一致（多字、漏字），這份錄音整份不用。
2. whisper 聽寫整段 → 對回每個詞的位置（漏念的詞對不上）→ 在附近最安靜的地方下刀切開。
3. 每一段單獨再聽寫一次，和預期的詞比相似度：英語、中文 ≥ 0.75，日語 ≥ 0.6（漢字寫法和讀音取較高者）。通過才轉成 mp3，覆蓋 `public/audio/<lang>/<scene>/<itemId>.mp3`。
4. 沒過的詞集中再錄一份，最多 3 輪；還是沒過就保留第 1 層的 edge-tts 音檔。
5. 處理對象是「還沒通過驗收的詞」，跟 edge-tts 檔在不在無關，所以底稿最後都會被 ChatGPT 版本取代（除了驗收不過的）。

**來源標識**

- `content/voice/<scene>.json` 記錄通過驗收的詞，按語言分段，每個詞記：`heard`（whisper 聽到的）、`score`、`take`（哪一份錄音）、`account`（哪個 ChatGPT 帳號，例如 chatgpt1）。
- 不在這份記錄裡的詞就是 edge-tts。edge-tts 沒有自己的記錄，mp3 檔本身也沒有來源資訊，目前只能靠「不在記錄裡」推斷。

**進度（2026-09-22）**：公園英語 31/33、中文 10/33 已換成 ChatGPT 的聲音；日語和其他場景都還是 edge-tts。

**待補**

- edge-tts 的詞也要寫記錄（來源、聲音、念的文字），讓每個音檔都有明確來源，不靠推斷。
- 記錄要存「念的文字」：現在兩層都只看 itemId 或檔案在不在，單字改了（例如改譯名）不會重錄，會留下舊的發音。
- 自動擴展的整合步驟只跑 build-audio，所以新場景只有 edge-tts；要把 build-voice 接進去（需要 ChatGPT 帳號、ffmpeg、whisper，一個場景 × 3 種語言至少錄 3 份）。
- ChatGPT 版本還沒有人工聽過；不同帳號（chatgpt1、chatgpt2）的聲音可能不一樣。

### 3.6 技術設計摘要（TDD）

內容以資料驅動。手畫的前 4 個場景地形在 `WorldBackground.tsx`；之後的場景由自動擴展產生（規劃 `content/plans/<scene>.json` → manifest → 街區模板地形，見 [expansion.md](expansion.md)）。管線：

```
content/svg-manifests/<scene>.json   單字（中/英/日+讀音）、物品描述 ← 唯一來源
        │ miko-ws 生成 SVG → npm run content:sync-svg
public/svg/<scene>/<itemId>.svg
content/scene-config.json            區域（地圖矩形）、地帶、成群、散落、動態
        │ npm run content:layout -- <scene>
content/layouts/<scene>.json         鎖定的位置（可手改）
        │ npm run content:scenes（清洗 SVG + 檢查擺放 / 動態 / id 重複）
src/data/scenes/<scene>.json         遊戲讀的資料（產出物，不要手改）
        │ npm run content:audio（edge-tts）
public/audio/<en|ja>/<scene>/<itemId>.mp3
```

場景 JSON 裡每個物品的欄位：

```json
{
  "id": "bench", "zone": "entrance", "category": "...",
  "words": { "zh-TW": "長椅", "en": "bench", "ja": { "text": "ベンチ", "reading": "ベンチ" } },
  "viewBox": [0, 0, 200, 120], "body": "<清洗過的 SVG 內文>",
  "x": 120, "y": 410, "w": 180, "h": 108, "rotate": 0, "flip": false,
  "motion": { "type": "sway", "dur": 4, "delay": -1.2, "amp": 1 }
}
```

- 座標都是整張地圖的座標；音檔路徑由場景 id + 物品 id 推出來，不寫在 JSON。
- 關卡定義在程式（`src/lib/stages.ts`），所有場景共用，不寫在場景 JSON。
- 原規劃的「場景擺放工具」改成 seed 自動擺放 + 手改鎖定檔 + 預覽圖（`npm run content:scene-preview`），不另做拖放工具。
- 物件音效（`sfx`）欄位還沒有。

## 7. 主要風險

| 風險 | 影響 | 對策 |
| --- | --- | --- |
| 找物好玩但學不到（或反之） | 核心價值不成立 | 原型階段就測隔天回憶率——**試玩還沒辦** |
| 美術 / 配音成本超支 | 回本困難 | M2 測出單場景工時後再排 Alpha 範圍 |
| 手機上小物品難點擊 | 挫折感 | 最小點擊尺寸規範、縮放、提示系統 |
| 手機效能未實測 | 動畫卡頓、耗電 | 真機測試；開「減少動態」可全部停止；畫面外的街區已暫停動畫 |
| 每場景物品數低於目標 | 可學單字量、找物難度不足 | 補動物 / 人物或新物件；或下修目標（第 8 節） |
| 會動的物件變成「可點」線索 | 找物變簡單 | 會動物件 ≤ 30%，每個區域背景也有動態 |
| 物件位置上線後不能改 | 美術重生、擺放調整受限 | 上線前定稿擺放；build 時檢查遮擋與區域 |
| TTS 讀音錯誤 | 學到錯的發音 | 母語者檢查一輪；核心詞改真人錄音 |
| 重複遊玩膩 | 留存低 | 四階段遞進 + 每日複習 + 新場景包 |
| 多語言擴展成本 | 內容量倍增 | 物件圖不含文字；單字與音檔按語言獨立存放 |
