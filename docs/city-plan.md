# 城市規劃 v1：從「平面格子」到「街景小鎮」

> 日期：2026-09-23｜狀態：P1–P5 已實作、借了 staging 的情境擺放；**還沒 commit，自動擴展暫停中**（見 §10）｜依據：`docs/scene-preview/town.png`、`GeneratedDistrict.tsx`、`district-kit.mjs`

## 0. 現況診斷

看 `town.png`，只有核心 4 區（公園、商業街、河、超市）像城市，其餘 10 個自動擴展街區有 5 個問題：

| 問題 | 證據 | 城市規劃的說法 |
|---|---|---|
| 沒有路網 | 街區彼此直接貼著，用棕色牆隔開；只有商業街有一條完整道路 | 缺「街道骨架」，每個街廓都該臨街 |
| 看不到建築 | 室內區是「無屋頂剖面」的地板 + 後牆，看起來像平面圖、不像房子 | 缺建築量體、立面、屋頂 |
| 沒有高度層次 | 全部同一平面，沒有陰影、沒有高低 | 3/4 視角沒有被用來表現「立體」 |
| 土地使用隨機 | slot 依序填：機場在圖書館旁邊、海邊在內陸 | 缺分區（商業 / 公共 / 住宅 / 濱水 / 郊區） |
| 東側大片空地 | 6200 以東一半是空白草地 | 缺城市邊緣與遠景 |

另外有一個設計限制要先處理：`scene-standard.md` §0.4 禁止背景畫樹、路燈、斑馬線、長椅（因為它們是單字）。**城市街景最需要的正是這些**，所以要先訂「背景 vs 物品」的視覺語言（§2）。

## 1. 規劃框架：Kevin Lynch 城市意象五要素

這是記憶遊戲，玩家靠「空間」記單字；Lynch 的五要素剛好就是人記住城市的方式，每個要素對應一個實作項目：

| 要素 | 小鎮裡的對應 | 為什麼對記憶有用 |
|---|---|---|
| 路徑 Paths | 主幹道、次要街道、河岸步道、鐵道 | 玩家沿路描述位置：「火車站前那條路右邊」 |
| 邊界 Edges | 河、鐵道、海岸線、城牆綠帶 | 把地圖切成幾大塊，降低迷路 |
| 分區 Districts | 5 種土地使用，各有地面色調與建築風格 | 一眼認出「我在住宅區」 |
| 節點 Nodes | 十字路口、車站前廣場、圓環 | 高辨識度的交會點 |
| 地標 Landmarks | 鐘塔、燈塔、摩天輪、水塔（背景、不可點） | 縮小看全圖時的方位錨點 |

## 2. 視覺語言：兩種投影分開「背景」和「物品」

**原則：物品用正面立面（現狀），背景基礎設施用俯視平面。**

- 行道樹 → 俯視的圓形樹冠（深綠圓 + 陰影），不是正面的樹幹樹冠 `tree` 物品
- 路燈 → 地上一個小圓點 + 光暈，不畫燈桿
- 斑馬線 → 路面上的白色條紋（平貼地面、跟道路一起畫），和直立的 `crosswalk` 物品視覺上不同
- 屋頂 → 俯視屋頂色塊 + 屋脊線

這樣背景可以滿是城市元素，但玩家不會誤點，因為「直立的才能點」。需修改 `scene-standard.md` §0.4 的措辭（禁止「正面畫法的」樹、路燈…，允許俯視的）。

## 3. 路網（最重要，先做）

```
 ═══ 主幹道（雙向四線，公車路線）  ─── 次要街道（雙向兩線）  ┄┄┄ 巷弄 / 步道
 ▓▓▓ 鐵道（東西向，車站所在）       ≈≈≈ 河

        公園        ≈河≈   濱水區
 ─────商業街────────橋───────────────────── 主幹道 A（東西）
        超市        ≈≈≈    公共區
 ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓ 車站 ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓ 鐵道（邊界）
        住宅區      ≈≈≈    商業核心
 ─────────────────橋─────────────────────── 主幹道 B（東西）
        郊區 / 農場  ≈≈≈→ 海邊
     │               │                │
  次要街道（南北，每個 slot 之間一條）
```

- **每個 slot 之間留 240 寬的街道走廊**（原訂 200，實作用 240：人行道 50×2 + 車道 140）（南北向次要街道、東西向在每排之間）。十字路口畫斑馬線平貼路面、路口轉角圓弧、中央一個俯視圓環（其中一個做成噴水池圓環當節點）。
- **河上的橋**：主幹道 A、B 各一座（背景，平貼路面延伸過河），讓東西兩岸連通。
- **鐵道**當作一條邊界，車站跨在鐵道上。
- 每個街區至少一面臨街；室內區的「門」開在臨街那面。

## 4. 街廓：每個街區 = 一棟或幾棟建築 + 臨街帶

把現在的「區域矩形」重新詮釋成街廓的剖面，從北（後）到南（前）分 4 層，這就是 3/4 視角的「立體」：

```
 ┌────────────────────────────────┐
 │ ① 屋頂帶（俯視屋頂、水塔、空調）  │ ← 高度：屋頂高低錯落，投影往右下
 │ ② 立面帶（二、三樓窗戶、陽台）    │ ← 顯示建築有幾層樓
 ├────────────────────────────────┤
 │ ③ 剖面室內（現在的地板 + 物品）   │ ← 不動，物品位置不變
 ├────────────────────────────────┤
 │ ④ 臨街帶：人行道 + 行道樹 + 路緣  │ ← 接上 §3 的街道
 └────────────────────────────────┘
```

- 室內區保留「剖面」（玩家要看到裡面的東西），但在剖面**上方**加 ①② 讓它看起來是一棟樓被切開，而不是一張平面圖；剖面兩側畫外牆厚度與陰影。
- 室外區（校園、機場跑道、海邊）不加建築，改加圍籬 / 綠籬 + 臨街入口。
- **陰影統一**：光源左上，所有建築、樹冠往右下投 20–40 的半透明陰影 → 最便宜的「立體感」。
- **建築高度對應分區**：商業核心 3–5 樓、公共建築 2–3 樓（有屋頂特徵：學校鐘樓、消防局瞭望塔、醫院頂樓直升機坪）、住宅 1–2 樓斜屋頂、郊區平房。
